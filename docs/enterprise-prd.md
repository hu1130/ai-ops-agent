# AI Ops Agent 企业版 PRD

## 1. 产品定位

AI Ops Agent 是面向中小企业和交付团队的智能运维平台，用 AI 辅助完成服务监控、故障识别、日志分析、告警通知、恢复跟踪和处理建议。

当前内部 MVP 已经验证：

- 单服务器监控可行
- 官网和 API 可用性监控可行
- AI 客服真实问答探针可行
- Docker 日志新增错误监控可行
- QQ 邮箱告警可行
- 连续失败告警、恢复通知、日报机制可行

企业版目标是把这些能力产品化，支持多服务器、多项目、多团队、多告警渠道和私有化部署。

## 2. 目标用户

### 2.1 核心用户

- 没有专职运维的小公司
- 软件外包和交付团队
- SaaS 创业团队
- 有多个 AI 应用或官网项目的企业
- 需要私有化交付的技术服务商

### 2.2 典型角色

- 企业老板：想知道系统有没有稳定运行
- 技术负责人：想快速定位问题
- 开发人员：需要日志和上下文
- 运维人员：需要告警、趋势和处理记录
- 客户成功：需要知道客户系统是否正常

## 3. 核心痛点

1. 产品上线后没人盯，用户先发现问题。
2. 出问题时不知道是服务器、代码、数据库、模型接口还是第三方服务的问题。
3. 日志散落在服务器和容器里，不会查或查得慢。
4. 告警太吵，一次偶发波动就轰炸。
5. 故障恢复后没人通知。
6. 没有日报、周报和可用率记录。
7. 多项目、多服务器后配置混乱。
8. 企业客户要求数据不出内网，需要私有化部署。

## 4. 产品目标

### 4.1 短期目标

- 让内部项目稳定运行。
- 告警少而准。
- 每次告警带上下文和处理建议。
- 形成可复用的交付模板。

### 4.2 中期目标

- 支持多项目、多服务器。
- 提供 Web 管理后台。
- 支持邮件、飞书、企业微信、Webhook。
- 提供事件中心、日报和趋势图。

### 4.3 长期目标

- 形成企业级 AI 运维平台。
- 支持私有化部署。
- 支持插件扩展。
- 支持半自动修复和人工审批。
- 支持多租户商业化。

## 6. 功能模块

### 6.1 资产管理

管理企业的运维对象：

- 服务器
- 域名
- 项目
- 容器
- 数据库
- 第三方 API
- AI 模型接口
- 日志文件

### 6.2 监控中心

支持以下监控类型：

- HTTP 页面监控
- API 健康检查
- JSON API 业务探针
- AI 对话探针
- Docker 容器状态
- CPU、内存、磁盘
- 日志新增错误
- 数据库连通性
- 第三方服务状态

### 6.3 告警中心

支持：

- 连续失败阈值
- 告警去重
- 冷却时间
- 恢复通知
- 告警等级
- 邮件
- 飞书
- 企业微信
- Webhook
- 后续扩展短信和电话

### 6.4 智能诊断

告警时自动收集：

- 最近错误日志
- 容器状态
- 资源快照
- 最近部署时间
- 依赖服务状态
- 历史相似故障

输出：

- 可能原因
- 排查顺序
- 建议命令
- 风险提示

### 6.5 事件中心

记录每次故障：

- 发现时间
- 恢复时间
- 持续时长
- 影响项目
- 告警内容
- 处理人
- 处理记录
- 复盘结论

### 6.6 报表中心

提供：

- 日报
- 周报
- 可用率
- 平均响应时间
- 故障次数
- 告警分类
- 最常见故障原因

### 6.7 自动化处置

分阶段启用：

- 第一阶段：只给建议
- 第二阶段：低风险自动操作
- 第三阶段：高风险操作人工确认

低风险动作：

- 重启已挂掉的容器
- 清理过期临时文件
- 轮转日志
- 重新执行健康探针

高风险动作：

- 重启数据库
- 删除文件
- 切换生产流量
- 修改配置

## 7. 非功能要求

### 7.1 安全

- 密钥不进入 Git 仓库
- 配置文件权限收紧
- Web 管理后台必须登录
- 操作记录必须审计
- 支持内网部署

### 7.2 可用性

- Agent 异常后自动重启
- Server 异常不影响被监控业务
- 告警失败要记录本地日志
- 数据库需可备份和迁移

### 7.3 可扩展性

- 监控类型插件化
- 告警渠道插件化
- 诊断规则插件化
- 支持后续接 Kubernetes 和云厂商 API

## 8. 商业化方向

### 8.1 私有化部署

面向企业客户：

- 一次性部署费
- 年度维护费
- 定制集成费

### 8.2 SaaS 版本

面向中小团队：

- 免费版：少量监控目标
- 专业版：多项目、多渠道、报表
- 企业版：私有化、审计、自动化处置
